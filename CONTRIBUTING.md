## Code of Conduct
We expect all contributors to follow the [Code of Conduct](https://github.com/CodeMaverick2/Chess_group-16/blob/main/CODE_OF_CONDUCT.md). Please be respectful and considerate when interacting with the community.

## How to Contribute

### 1. Fork the Repository
Before starting your work, make sure to fork this repository to your GitHub account. You can do this by clicking the "Fork" button at the top-right corner of the repository page.

### 2. Clone the Repository
After forking, clone the repository to your local machine using the following command:
```bash
git clone https://github.com/codemaverick2/Chess_group-16.git
```

### 3. Set Up Your Environment
Make sure you have **Node.js** installed on your system. Install the project dependencies by running:
```bash
npm install
```

### 4. Create a New Branch
Create a new branch for your changes:
```bash
git checkout -b <your-branch-name>
```
Make sure to give your branch a descriptive name, such as `feature-add-knight-move` or `bugfix-board-toggle`.

### 5. Make Your Changes
Contribute code related to bug fixes, new features, or other improvements. Ensure your changes follow the [Style Guidelines](#style-guidelines).

### 6. Commit Your Changes
Once you're done, stage and commit your changes:
```bash
git add .
git commit -m "Brief description of your changes"
```
Make sure to write clear and concise commit messages following the [Commit Message Guidelines](#commit-messages).

### 7. Push to Your Fork
Push your changes to your forked repository:
```bash
git push origin <your-branch-name>
```

### 8. Create a Pull Request
Once your changes are pushed, go to the original repository and create a pull request from your fork. In your pull request, please include the following:
- A detailed description of your changes.
- A reference to the issue you are solving (if applicable).

## Reporting Bugs
If you find a bug, please create a new issue in the repository. When reporting bugs, provide as much detail as possible:
- Steps to reproduce the bug.
- Expected behavior vs. actual behavior.
- Screenshots (if applicable).
- Your environment (OS, browser, etc.).

## Feature Requests
If you have a feature request, feel free to open an issue describing the feature in detail. Make sure to explain the benefits and how it can improve the project.

## Submitting Pull Requests
Please ensure that your pull request:
- Is well-documented.
- Passes all tests.
- Is properly formatted according to the project's coding standards.

We will review your pull request as soon as possible. If changes are requested, kindly address them promptly.

## Style Guidelines
Please follow these style guidelines when contributing:
- **JavaScript**: Follow the [Airbnb JavaScript Style Guide](https://github.com/airbnb/javascript) with the use of `eslint`.
- **CSS**: Ensure proper formatting and comment your code if necessary.
- **HTML**: Use proper indentation and semantic tags for readability.

## Commit Messages
Write clear, concise, and meaningful commit messages. Here’s a format you can follow:
- Use the imperative mood (`Add feature`, `Fix bug`, not `Added feature`).
- Keep the subject line under 50 characters.
- Reference any issue numbers if applicable.

Example:
```
Add dynamic board resizing functionality (#23)
```
